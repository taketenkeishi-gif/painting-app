実装方針 追補：PowerShellログ・パス・Nativeコマンド再発防止ルール
この追補は、既存の「開発方式・実装プロセス統合方針」の末尾に追加する前提の汎用ルールである。目的は、PowerShell実行時のエラー誤検知、ログ未出力、notepad未起動、相対パス誤り、Git警告による途中停止を再発させないこと。
26. パスは冒頭で定義し、以後は変数だけを使う
各PowerShellスクリプトでは、プロジェクト固有のパスを冒頭に集約する。本文中に同じパス文字列を何度も直接書かない。
プロジェクトごとに変更してよいのは、原則として以下だけにする。
```powershell
$ProjectRoot = "<対象プロジェクトのルートディレクトリ>"
$WorkRoot = "<ログ・一時ファイルを出力する作業用ディレクトリ>"

$Out = Join-Path $WorkRoot "実行ログ.txt"
$PatchScript = Join-Path $WorkRoot "実行中パッチ.ps1"
$Tmp = Join-Path $WorkRoot "実行中パッチ.tmp"
```
`$ProjectRoot` は、Gitリポジトリまたは対象プロジェクトのルートディレクトリを指す。
`$WorkRoot` は、ログ・一時スクリプト・検証結果を出力する作業用ディレクトリを指す。
以後のファイル指定は、必ず `Join-Path` またはこの変数から作る。
例:
```powershell
$TargetFile = Join-Path $ProjectRoot "<対象ファイルの相対パス>"
$RunScript = Join-Path $ProjectRoot "<起動スクリプトの相対パス>"
$BuildScript = Join-Path $ProjectRoot "<ビルドスクリプトの相対パス>"
$TestScript = Join-Path $ProjectRoot "<テストスクリプトの相対パス>"
```
禁止:
```powershell
& ".\run.ps1" -Config Release
```
理由: カレントディレクトリがずれると失敗する。起動・ビルド・テストは常に絶対パス化したスクリプトを実行する。
27. 相対パスは、Set-Location成功後にしか使わない
スクリプトの最初で必ずリポジトリ実在確認を行う。
```powershell
if (-not (Test-Path -LiteralPath $ProjectRoot)) {
  throw "ProjectRoot not found: $ProjectRoot"
}

Set-Location -LiteralPath $ProjectRoot

$inside = (& git rev-parse --show-toplevel 2>$null)
if ($LASTEXITCODE -ne 0) {
  throw "Not a git repository: $ProjectRoot"
}
```
ただし、`Set-Location` が成功しても、実行対象ファイルは毎回 `Test-Path` で確認する。
例:
```powershell
if (-not (Test-Path -LiteralPath $RunScript)) {
  throw "Run script not found: $RunScript"
}
```
28. NativeコマンドのstderrをPowerShellエラーとして扱わない
Git / CMake / MSBuild などのNativeコマンドは、終了コードが0でもstderrに警告を書くことがある。
例:
```text
git: warning: LF will be replaced by CRLF the next time Git touches it
```
これはGitの警告であり、Gitコマンド失敗とは限らない。
禁止:
```powershell
git diff --name-status *>&1 | Out-File $Out -Append -Encoding UTF8
git diff --name-status 2>&1 | Out-File $Out -Append -Encoding UTF8
```
理由: Windows PowerShellでは、NativeコマンドのstderrをPowerShellの出力ストリームへ混ぜると、`NativeCommandError` として扱われ、`$ErrorActionPreference = "Stop"` により途中停止する場合がある。
原則:
Nativeコマンドの成功/失敗は、stderrの有無ではなく `$LASTEXITCODE` だけで判定する。
29. Nativeコマンドの標準ログ関数
Git / CMake / MSBuild / exe実行などは、原則として以下の関数を通す。
```powershell
function Add-Log {
  param([string]$Message)
  $Message | Out-File -LiteralPath $Out -Append -Encoding UTF8
}

function Invoke-NativeLogged {
  param(
    [string]$Title,
    [string]$FilePath,
    [string[]]$ArgumentList
  )

  Add-Log ""
  Add-Log "=== $Title ==="
  Add-Log ("> " + $FilePath + " " + ($ArgumentList -join " "))

  & $FilePath @ArgumentList 1>> $Out 2>> $Out
  $code = $LASTEXITCODE

  Add-Log ("exit code: " + $code)

  if ($code -ne 0) {
    throw "FAILED: $Title"
  }
}
```
使用例:
```powershell
Invoke-NativeLogged "git status" "git" @("status", "--short", "--branch")
Invoke-NativeLogged "git diff name-status" "git" @("diff", "--name-status", "--", $RelativeTargetPath)
Invoke-NativeLogged "build" "powershell" @("-NoProfile", "-ExecutionPolicy", "Bypass", "-File", $BuildScript)
```
この方式では、stderrの警告はログに残るが、それだけでは停止しない。停止条件は終了コードが非0の場合だけにする。
30. notepadはfinallyで必ず開く
`notepad $Out` を通常処理の最後だけに置くと、途中でエラーが出た場合にログが開かれない。
標準形:
```powershell
$ErrorActionPreference = "Stop"

try {
  # ここに処理本体を書く
}
catch {
  "" | Out-File -LiteralPath $Out -Append -Encoding UTF8
  "=== SCRIPT ERROR ===" | Out-File -LiteralPath $Out -Append -Encoding UTF8
  $_ | Out-File -LiteralPath $Out -Append -Encoding UTF8
  throw
}
finally {
  if (Test-Path -LiteralPath $Out) {
    Start-Process notepad.exe -ArgumentList $Out
  }
}
```
目的:
エラー時もログを確実に開く
どの行で止まったかを確認できる
チャット欄に途中ログを直接貼る必要を減らす
31. PowerShellスクリプト生成時は here-string を使う
長いスクリプトをチャットから直接貼ると、途中改行、全角スペース、余計な文字、貼り付けミスで壊れる。
標準方式:
```powershell
$WorkRoot = "<ログ・一時ファイルを出力する作業用ディレクトリ>"
$PatchScript = Join-Path $WorkRoot "実行中パッチ.ps1"

@'
# ここに実行スクリプト本体を書く
'@ | Set-Content -LiteralPath $PatchScript -Encoding UTF8

powershell -NoProfile -ExecutionPolicy Bypass -File $PatchScript
```
禁止:
長い処理をREPLへ分割貼り付けする
`}` の直後に不要な文字が混入した状態で実行する
`notepad $Out` だけを最後に置いて、エラー時のログ開封を期待する
32. Git警告と失敗を分ける
Gitのstderr出力には、警告と失敗が混在する。以下は別物として扱う。
警告例:
```text
warning: LF will be replaced by CRLF
```
失敗例:
```text
fatal: not a git repository
error: pathspec did not match any file(s) known to git
```
判定ルール:
```text
$LASTEXITCODE = 0  → 続行してよい
$LASTEXITCODE != 0 → 停止する
```
stderrに文字が出たこと自体を失敗条件にしない。
33. 観測用と変更用でログ関数を分けない
観測用PowerShellでも変更用PowerShellでも、ログの出し方は同じにする。
理由:
ログ形式が統一される
エラー発生位置が追いやすい
「観測では動くが変更では落ちる」という差を減らせる
共通で使う項目:
```text
=== phase ===
=== repo ===
=== status before ===
=== target check ===
=== operation ===
=== status after ===
=== diff ===
=== result ===
=== SCRIPT ERROR ===
```
34. ビルド・起動は必ず専用フェーズに分離する
変更用PowerShellには、原則としてbuild / runを入れない。
例外的に入れる場合でも、以下を満たすこと。
対象ファイルのdiff確認が先に完了している
`BuildScript` / `RunScript` の実在確認が済んでいる
絶対パスで実行している
Nativeコマンドログ関数を通している
通常は以下のように分ける。
```text
1. APPLY ONLY
   ソース変更だけ

2. VERIFY ONLY
   Select-String / git diffだけ

3. BUILD ONLY
   対象プロジェクトのビルドコマンドだけ

4. RUN ONLY
   対象プロジェクトの起動コマンドだけ
```
35. 起動スクリプトの場所は推測しない
起動スクリプトはプロジェクトによって場所が違う。
確認順:
```powershell
$RunScriptCandidates = @(
  (Join-Path $ProjectRoot "run.ps1"),
  (Join-Path $ProjectRoot "scripts\run.ps1"),
  (Join-Path $ProjectRoot "tools\run.ps1")
)

$RunScript = $null
foreach ($candidate in $RunScriptCandidates) {
  if (Test-Path -LiteralPath $candidate) {
    $RunScript = $candidate
    break
  }
}

if ($null -eq $RunScript) {
  throw "Run script not found. Checked: $($RunScriptCandidates -join ', ')"
}
```
見つかった実在パスだけを使う。
候補にない場所へ置かれているプロジェクトでは、推測で実行せず、候補配列に実在パスを明示的に追加する。
36. 失敗時に次の修正へ進まない
以下のどれかが起きたら、そのターンでは次の実装に進まない。
repo確認失敗
対象ファイル未発見
アンカー0件
アンカー2件以上
置換後に旧文字列が残る
置換後に新文字列が出ない
git diffが想定外
Nativeコマンド終了コードが非0
ログが開かなかった
次にやることは「原因特定の観測」だけにする。
37. APPLY後の最低限チェック
APPLY ONLYの最後には、最低限以下を出す。
```powershell
Invoke-NativeLogged "git status after" "git" @("status", "--short", "--branch")
Invoke-NativeLogged "git diff name-status after" "git" @("diff", "--name-status")
Invoke-NativeLogged "git diff target" "git" @("diff", "--", $RelativeTargetPath)
```
ただし `$RelativeTargetPath` は、Gitで扱える `/` 区切りの相対パスを明示して使う。
例:
```powershell
$RelativeTargetPath = "src/path/to/TargetFile.ext"
```
絶対パスとGit相対パスを混同しない。
38. これ以上の一括自動化をしない基準
以下の状態になったら、PowerShell自動パッチを止める。
実装前の状態に戻っただけで、目的に近づいていない
表層的な設定変更だけでは意図した結果にならない
既存構造の把握不足で壊れたファイルが出た
1回のパッチで複数ファイルが想定外に変化した
Git警告やstderr処理でスクリプト自体が不安定
この場合は、次の一手を「実装」ではなく「構造観測」に戻す。
39. 今回の具体的再発防止メモ
今回起きた問題は以下。
Nativeコマンドのstderr警告をPowerShellが `NativeCommandError` として扱い、途中停止した。
`notepad $Out` が通常処理の最後にあったため、エラー時にログが開かれなかった。
`git diff --name-status *>&1 | Out-File ...` のように、Nativeコマンド出力をパイプに流していた。
相対パスを使い、実在パス確認が不十分だった。
変更用スクリプトと確認用スクリプトの責務が混ざっていた。
今後の対策は以下。
Git / CMake / MSBuild / run は必ず `Invoke-NativeLogged` を通す。
stderr出力ではなく終了コードで失敗判定する。
`notepad` は `finally` で必ず開く。
起動・ビルドスクリプトは `Join-Path` と `Test-Path` で実在確認する。
APPLY / VERIFY / BUILD / RUN を別フェーズに分ける。
1つでもエラーが出たら次の実装に進まない。
40. 最終追加ルール
PowerShellパッチでは、以下を標準にする。
```text
パスは冒頭に集約する
Nativeコマンドはパイプに流さない
stderrの有無ではなく終了コードで判定する
notepadはfinallyで開く
起動・ビルドスクリプトは絶対パス化して実在確認する
APPLYとBUILDとRUNを混ぜない
エラー後は実装を止めて観測に戻る
```
最大の教訓:
PowerShellでは、ソースコードの置換ミスだけでなく、ログ取得・stderr処理・相対パス・貼り付け方法そのものが事故原因になる。したがって、実装精度以前に、スクリプト実行基盤を固定化する。
