# Product Specification — Paint App

## ビジョン

**CLIP STUDIO PAINT / Krita 同等以上の描画品質**をベースに、
将来的に静止画MV制作ソフトと連携する「自分に最適化されたクリエイティブスイート」の中核アプリ。

AdobeでいえばPhotoshop + After Effectsの関係を、
独自スタック・ローカルファーストで実現する。

---

## 実装方針

### GPU（RTX 3060）フルスペック活用・常時高品質

- **GPU を積極的に活用**: RTX 3060 の VRAM・計算能力をフルスペックで活かす。レンダリング・合成・AI推論はすべて GPU を前提とする
- **Skia は GPU バックエンド（Metal / Vulkan / OpenGL）で統合**: `GrContext` でアクセラレーションを最大化。CPU フォールバックは画面外合成など限定的な用途に留める
- **作業中も高品質を維持する**: 「ドラッグ中は粗くして後で高品質に」という 2 パスアプローチは取らない。ストローク入力・変形・合成のどのフェーズでも常に最終品質と同等の描画を行う
- **品質を落とす最適化は禁止**: LOD 切り替え・解像度ダウンサンプル・スキップフレームなど、ユーザーが目にする品質を下げる最適化は行わない。GPU で高速化できない部分はアルゴリズム改善か OSS 吸収で対処する

---

## 外部依存の原則

- **API はボトルネックにしない**: 描画・レンダリング・AIはすべてローカル実行を基本とする
- OSSライブラリは積極的に吸収するが、ネットワーク必須の外部サービスには依存しない
- クラウド連携はオプション機能に限定し、オフラインでフル機能が使えること

## フェーズ構成

### Phase 0 — 描画エンジン根本再構築（最優先・現在地）

**目標**: CSP / Krita レベルの描画品質。ここが全ての基盤。

#### 0-1. レンダリングバックエンドを Skia に移行
- 現状の手書き CPU ピクセルループを **Google Skia** で置き換える
- Skia は Chrome / Flutter / Android が使う産業用2Dエンジン
- アンチエイリアス・サブピクセル精度・GPU アクセラレーションが標準
- API ボトルネックなし（ローカルライブラリ、MIT ライセンス互換）
- `PixelBuffer` を `SkBitmap` / `SkSurface` にマッピングする変換層を作る
- Qt との接続: `SkBitmap → QImage` の変換は `src/platform/qt` に閉じ込める

#### 0-2. ブラシエンジンを本実装に置き換え
- 現状の `gaussianFalloff` 手書きループは **暫定実装**
- **libmypaint**（MyPaint / GIMP が使うブラシエンジン）を統合、またはSkiaのパスストロークを活用
- 実装するブラシ品質要件:
  - サブピクセル精度のスタンプ配置
  - 筆圧カーブ（リニア / 指数 / カスタムベジェ）
  - 速度感応（速く動かすと滲む、等）
  - テクスチャオーバーレイ（紙質・キャンバス目）
  - ウェットミックス / スメア（絵具が混ざる感覚）

#### 0-3. ベクターレイヤーの AA 描画
- 現状の `stampCircle` / `drawSegment` 整数演算を完全廃止
- Skia の `SkPath` + `SkPaint` でベクター描画（AA は Skia が自動処理）
- ストローク品質: 可変幅、筆圧感応、ベジェ補間

#### 0-4. アンチエイリアス制御の実装
- `BrushSettings.antiAlias` フラグを実際に機能させる
- AA ON: Gaussian/Skia フルレンダリング
- AA OFF: ハードエッジ（ピクセルアート向け）
- `ToolPropertyPanel` に UI 追加

## 技術スタック選定

| 層 | 採用技術 | 理由 |
|----|---------|------|
| 2D レンダリング | **Skia** | Chrome/Flutter 実績、AA・GPU標準、ローカル |
| ブラシエンジン | **libmypaint** or Skia Path | MyPaint/GIMP実績、OSSで吸収可 |
| UI フレームワーク | **Qt6 Widgets** | 現状維持、Skia と共存可能 |
| GPU バックエンド | Skia + OpenGL (将来 Vulkan) | Skia が抽象化してくれる |
| AI ランタイム | **llama.cpp / stable-diffusion.cpp** | 完全ローカル、APIなし |
| プロセス間通信 | 共有メモリ / Named Pipe (Windows) | MVソフト連携、レイテンシ最小 |
| ファイル形式 | SQLite ベース独自形式 | レイヤー構造をトランザクション管理 |

## 移行戦略

### Skia 統合のステップ
1. `src/platform/skia/` ディレクトリを新設
2. `SkSurface` を `PixelBuffer` の裏側に置く（インターフェース変えずに内部置換）
3. `Renderer::compositeInto` を Skia の `SkCanvas::drawBitmap` ベースに書き換え
4. `BrushTool::stampAt` を `SkCanvas` へのパス描画に置き換え
5. Qt 表示は `SkBitmap::pixmap()` → `QImage::fromData()` で継続

### libmypaint 統合のステップ
1. vcpkg または手動ビルドで `libmypaint` を取得
2. `BrushTool` の `strokeSegment` をラッパーに置き換え
3. `BrushSettings` を libmypaint のブラシ設定構造体にマッピング

## 現状の問題（引き継ぎ時点）

- `Renderer.cpp::stampCircle` — 整数演算、完全ジャギ（ベクター描画）
- `Renderer.cpp::drawSegment` — ピクセル単位ステップ、斜め線が階段状
- `BrushSettings.antiAlias` — 定義のみ、実装なし
- `angle / roundness / taperStart / taperEnd` — `BrushTool` に実装済みだが UI 未接続
- ペンタブ入力 — マウスイベントのみ、筆圧未取得
